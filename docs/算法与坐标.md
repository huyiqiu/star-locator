# Star16-v2 算法与坐标定义

## 与参考论文的关系

参考 Zhou 等，2016，*A high precision visual localization sensor and its working methodology for an indoor mobile robot*，DOI: [10.1631/FITEE.1500272](https://doi.org/10.1631/FITEE.1500272)。

论文采用回归反光圆点、红外补光相机、4×4 空间网格、三个固定方向点、十二个可选编码点及 P3P 位姿求解。本实现保留红外反光亮点的成像思路；以下码本和检测算法是独立的工程扩展，不是论文源码或商业定位器固件的复现，也不兼容其原始编号。

| 问题 | 本实现 |
| --- | --- |
| 稠密编号没有纠错余量 | 统一 18 个 ID，比较旋转与镜像后的 12 位码距，最小距离 3，支持 1 位纠错 |
| 三点轴向与透视下的线性插值 | 四角锚点建立透视单应性，在校正网格上解码 |
| 背景干扰和曝光变化 | 固定 / Otsu / 局部自适应分割、面积与圆度筛选、亮度加权中心 |
| 单块标记选择 | 支持多候选和多块标记，去除重复解释；优先有效位姿及靠近光轴的标记 |
| 三点位姿的多解 | 使用全部匹配点，保留 IPPE 候选，检查正深度、重投影和双解近似程度，再 LM 优化 |
| 置信度解释 | 返回几何质量评分，不把亮度评分宣称为概率、精度或协方差 |
| 图像与机器人坐标易混淆 | 同时输出正逆变换，显式区分标记、相机、世界和底盘 |
| 实机软件接入 | 参数持久化、棋盘标定、相机与上传输入、HTTP 与 WebSocket |
| 断流后旧位姿残留 | 独立采集线程、最新帧机制、新鲜度门限、断流清空 |

## 网格和编码

从打印图案正面观察，数组行向下、列向右。角点 `(r,c)=(0,0),(0,3),(3,3),(3,0)` 始终放置反光点。其他十二格按先行后列排列，跳过四角，第一格为最低位：

```text
 A  b0 b1  A
 b2 b3 b4 b5
 b6 b7 b8 b9
 A b10 b11 A
```

A 是固定锚点。不是反光点的格子保持低红外反射。四角负责几何，十二位编码同时决定 ID 与方向。四角图案本身对旋转对称，方向不能只靠角点得到。

所有码字的四种旋转、四种镜像共 144 个变体，任意两个不同变体的汉明距离至少为 3。解码只接受正面四种旋转；镜像图案不在接受集合中。

在正确恢复网格、四个锚点可见且错误只发生于编码格的前提下，一个错误位能唯一纠正。两个及以上错误不保证拒识，不能把质量评分视为其检测保证；严重的粘连、错分组或遮挡不能当作普通单点编码错误。

## 检测流程

1. 灰度化，按设置进行高斯平滑与阈值分割。
2. 提取外轮廓，检查面积、圆度、长宽比和图像边缘截断。以轮廓内正亮度权重计算浮点圆心，不把中心舍入为整数像素。
3. 有可用内参时，先校正圆心的畸变，再进行几何网格匹配。非等比例图像不使用旧内参。
4. 对邻接连通分组、按亮点排序的前缀、点邻域与点对中心邻域求凸包，提取四边形候选；不做无限制的全部四点组合。候选数量、亮点数和标记数均有上限。
5. 每个四边形只做一次透视校正，把圆心投影到 0–3 的网格，再旋转离散格点以验证四种正向方向。检查坐标残差、角锚点、占用格与空格，进行受限汉明解码。
6. 使用预期为真的全部匹配点再次估计单应性，检查像素重投影误差。编码纠错补回的缺失点不会作为真实观测加入 PnP；额外错误亮点也不会作为模型点加入 PnP。畸变反算不稳定时，允许对原图做完整且精确编码的回退识别，位姿结果明确标注为粗略估计。
7. 将格点变为毫米尺度的平面三维点，调用 `solvePnPGeneric(..., SOLVEPNP_IPPE)`。分别评估候选的正深度、板面朝向和误差；检查双解是否仍有明显旋转差异且误差接近；对较小误差解做 LM 优化。
8. 对已经解释相同亮点的重复候选去重，输出每块标记和一个主标记。不把相同物理 ID 重复安装的两块板假定成可区分的世界地标。

本实现使用 `SOLVEPNP_IPPE`，而非有严格四角顺序与正方形坐标要求的 `IPPE_SQUARE`；所有可见且匹配的点都参与最终 PnP。

参考：[OpenCV PnP 官方说明](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)、[相机标定官方接口](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)。

## 质量、歧义与坐标

`direction_deg` 是标记 +X 在校正图像平面内相对右侧的顺时针方向，范围 `[0,360)`；它不是机器人在世界系的航向角。`quarter_turn` 是该方向最接近的 90° 象限，不替代连续角度。

`quality_score` 结合编码错误数和网格拟合残差，并在位姿有歧义时降低分数。它只用于相对质量排序，不是经现场数据标定的概率，也不是用于卡尔曼滤波的测量协方差。

`pose_status` 可为：

- `valid`：通过当前几何门限，仍需现场精度验证。
- `approximate`：原图精确解码的边缘回退位姿；可能存在较大误差，地图位置使用单独的 `approximate_*` 字段。
- `ambiguous`：两个 IPPE 候选误差相差小于 0.25 px，且姿态分离大于 3°。当前实现返回选中的候选，同时保留误差列表与歧义标记，不输出世界 / 底盘结果。
- `calibration_required`：没有被明确标记为已标定的内参，或宽高比不一致。
- `reprojection_rejected`：图案可以解码，但位姿未通过有效性或重投影门限。

歧义标记是工程启发式，不是完整的不确定性估计。它未纳入可知安装朝向、时序连续性、IMU 或里程计约束。没有这些信息时，近正视平面容易存在不稳定性；不应仅用低重投影误差认定姿态精确。

采用列向量，点变换为：

```text
p_camera = R_camera_marker @ p_marker + t_camera_marker
T_marker_camera = inverse(T_camera_marker)
camera_center_in_marker = -R_camera_marker.T @ t_camera_marker
T_world_camera = T_world_marker @ T_marker_camera
T_world_robot = T_world_camera @ T_camera_robot
```

标记坐标点为 `[(col-1.5)*spacing_mm, (row-1.5)*spacing_mm, 0]`。其 +Z 朝板背面，故相机在板正面正视时，光心在标记系的 Z 通常为负。这不代表负距离；`distance_mm` 是标记中心至相机光心的欧氏距离。

## 当前边界与后续验证

当前支持通用 UVC、浏览器相机与图片输入，实时坐标可进行自适应时间平滑；没有厂商工业相机 SDK、ROS 驱动或 IMU / 轮编码器融合。算法不隐式预测失去的标记，也不输出编造的世界地图。

四个角锚点必须都可见。数据点可在码距条件下纠正一格错误；角点遮挡、点粘连、标记越界、过小成像、强透视、离焦和镜面假亮点都可能导致拒识。圆形反光片在大倾角下的图像椭圆中心与真实投影中心存在偏差，亮度加权中心也不是能消除全部光学误差的保证。

单帧直接求解未经融合的位置会有抖动。下一阶段应使用真实制作板、真实标定、测量尺 / 高精度定位真值，在多距离、多角度和不同曝光下记录 ID 误识别、漏检、位置 / 姿态误差和处理时间。再按实测噪声设计时间融合及异常门限。合成测试通过不能替代这一步。
